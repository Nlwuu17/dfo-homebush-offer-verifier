## 本版两项修改（相对 `7079e96`）

两项修改都没有改变 23 题中任何一题的判定，四类汇总与 `7079e96` 完全相同。

1. **未知商品范围按保守规则处理。** 资料里价格前面的文字，先剥掉说明性的部分（日期、「标题为」「另外」「在 … 购买」、计价基准、英文的品牌名和活动名），再剥掉已经认得的词。剩下的词当作范围限制：用户描述必须原文写出这个词，否则按规则 B 判「证据不足」。现有 23 题中，被识别为限定词的有「大杯」「大号」「特价品」「加配料」，都是真正的限制。合成测试覆盖了以下情况：
   - 「床品」不支持「全店」；
   - 「床品」与「床品」按原文匹配；
   - 「黑五期间全店」仍识别为全店；
   - 「标题为」「另外」「在 … 购买」不算限制。
2. **收窄 Outlet 检查。** 「Outlet 门店 / Outlet 全店」是门店类型，仍要求资料限定 Outlet；「Outlet 商品」是商品范围，按类别比对。件数和门槛连同具体数值一起比对；「额外」和「最高」一样，属于优惠本身，必须一致。

## NC20 仍然判错

NC20（Swarovski，「买 2 件 Outlet 商品额外 20% off」，冻结标签「适用」）现在只剩一个原因：N02 这一段的冻结摘要保留了传单原样的「日/月」写法 `through 5/11 – 1/12`，判定器无法可靠解析，按规则 E 当作没有明确档期。按约定，冻结摘要保持原样，所以 NC20 仍判「证据不足」。

修改前的另一个原因（Outlet 检查误伤「Outlet 商品」）已经消除。可以这样验证：只在临时副本里把这段日期改成明确的年-月-日格式，冻结数据本身不动，NC20 就会依据 N02 判出「适用」，件数、「额外」和「Outlet 商品」的范围都能对上。新的摘要模板要求日期一律换算成 `YYYY-MM-DD`，顺序不确定时注明、不换算，以后就不会再出现这种写法。

## A、B 两组的读取变化

两组的总读取份数都从 50 份减少到 44 份，判定没有变差。原因是新判定器更早得出结论，不再读完目录里不相关的活动页：

| 案例 | 基线路径 | 当前路径 |
| --- | --- | --- |
| NC03 | N04 → N02 → N01 | N04 → N02 |
| NC04 | N04 → N02 → N01 | N04 → N02 |
| NC07 | N06 → N02 → N01 | N06 → N02 |
| NC13 | N10 → N11 → N01 | N10 |
| NC19 | N02 → N01 | N02 |

C 组的数字来自固定路径重判，路径就是录制时的路径，模型调用为零。表中「第 k 步即可得出结论」只是说明；当前判定器真正运行时，C 组可能在那一步之后补查或停止，路径可能与录制不同。BF26 的 C 组录制使用旧停止规则（首次判出结论即停），已在逐题表中标出。
