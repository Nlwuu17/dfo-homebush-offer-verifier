# 标注规则

> 状态：**已定稿**（2026-11-26，悉尼时间）。待定项 A–F 以及「规则之间的先后」均由标注人确认，采用起草时的建议选项。规则 F 及「A 与 F 同时触及」于同日在任何评测运行之前澄清，见 F 节。定稿后不得为了提高某组的分数而修改规则；确实需要改的，要写明原因，并重标所有受影响的案例。

## 1. 要回答的问题

每个案例只回答一个问题：

> 在核对日（`as_of_date`，悉尼当地时间），用户描述的这条优惠（`offer`），能否在悉尼 DFO Homebush 的该品牌实体店使用？

只依据该案例 `catalogue` 列出的资料，不使用资料以外的常识、经验，也不考虑"店员可能会通融"这类情况。

## 2. 三个标签

| 标签 | 含义 |
| --- | --- |
| 适用 | 已列资料足以确认：在核对日，本店提供的优惠与用户描述的一致。 |
| 不适用 | 已列资料足以确认：在核对日，本店不能按用户描述使用这条优惠。 |
| 证据不足 | 已列资料既不足以确认「适用」，也不足以确认「不适用」。 |

「证据不足」是正式答案，不表示标注失败。拿不准时选它，不要猜。

### 首批案例作为先例（已定）

- **BF26-01 适用**：Homebush 自己发布了同一优惠和有效期。品牌优惠页说明了折扣基准，并写明限 Outlet；传单补充了会员条件。资料合起来覆盖了用户描述的全部条件。
- **BF26-02 不适用**：品牌条款明确排除 Factory Outlets，品牌门店目录确认 Homebush 门店属于这一类。两份资料合起来，才构成"不能用"的依据。
- **BF26-03 证据不足**：品牌只说"参加活动的门店"适用，没有资料把本店纳入或排除。本店传单上写的是另一条折扣不同的优惠。

## 3. 判断步骤

按顺序检查，在第一个能下结论的地方停下：

1. **有效期**：在核对日，对应的优惠是否有效？（见规则 A、E）
2. **本店范围**：资料是否把这条优惠落实到 DFO Homebush 的这家店？（见规则 C、D）
3. **内容一致**：资料写的折扣数值、适用范围（全店还是指定款）、价格基准（原价、RRP、折后价）和资格条件（会员、App、金额门槛），是否与用户描述一致？（见规则 B）
4. **冲突**：已列资料之间如果在上面任何一点上互相矛盾，按规则 F 处理。

## 4. 已定规则

### A. 核对日不在有效期内（还没开始，或已经结束）→ **不适用**

资料明确写了起止日期，而核对日不在其中，就等于明确说了"今天不能用"。

注意：现有判定器会直接跳过不在有效期内的资料，结果会落到「证据不足」。按本条规则，判定器需要修改。修改应在开发集上完成，不能参照留出集。

### B. 用户描述比资料写得更宽 → **证据不足**

例如，资料写"指定款"，用户说"全店"；资料有金额门槛或会员限制，用户的描述里没有。资料没有说用户描述的那条优惠不存在，只是没有支持它。这与 BF26-03 的先例一致：资料写的是另一条优惠时，判「证据不足」。

用户描述比资料**更窄**、但完全落在资料范围内的（例如资料写"全店"，用户说"某一类商品"），视为一致。

### C. 商场为本店发布了优惠页，但条款写着"只限某类门店"或"限参与门店" → **视为本店参与**

商场为 Homebush 这家店专门发布了这条优惠，本身就是本店参与的依据，与 BF26-01 一致（该案例的品牌优惠页也写着限 Outlet）。除非另有资料明确排除本店。

### D. 只有商场活动传单列出这条优惠，没有单独的优惠页 → **传单可以单独作为本店依据**

传单是 DFO Homebush 为本中心印发的，且有起止日期。传单上"信息可能变更"的通用说明不影响这一点；如果其他已列资料与传单矛盾，按 F 处理。

### E. 资料上的有效期缺失或明显印错 → **证据不足**

例如没有印日期，或者结束日早于开始日。这种情况下，无法确认核对日是否在有效期内。不按常理推断日期。

### F. 已列资料互相矛盾 → **证据不足**

针对同一条优惠，分别按各份资料核对用户指定的日期、门店和优惠条件。如果采用不同资料会改变当日能否按所述条件使用的结论，按 F 判「证据不足」。如果差异仅在起止日期，且核对日落在所有明确有效期内，则记录档期差异，继续按门店范围和优惠内容判断；如果核对日落在所有明确有效期外，则按 A 判「不适用」。

遇到会改变结论的冲突，不自行判断哪份资料为准。

（2026-11-26 澄清：原文只写「例如商场优惠页和传单写的折扣或日期不同」，没有说明不影响核对日结论的差异算不算矛盾。这次澄清在任何评测运行之前完成。）

### 规则之间的先后

- **A 与 F 同时触及**：按 F 的方法逐份核对同一条优惠的有效期。核对日落在所有明确有效期内的，只记录档期差异；落在所有明确有效期外的，按 A 判「不适用」；落在一部分资料的有效期内、另一部分之外，即采用不同资料会改变结论的，按 F 判「证据不足」。
- **C、D 与 B 同时触及**：先按 C 或 D 确认本店参与，再按 B 比较内容。内容比资料更宽的，判「证据不足」。

## 5. 填写方式

在 `labels_todo.json` 里，每个案例填三项：

- `label`：`适用`、`不适用` 或 `证据不足`。
- `reason`：一到两句话，说明依据哪条规则、哪份资料。例如"N03 与 N02 折扣不同，按 F1 判证据不足"。
- `supporting_evidence_ids`：支撑结论所需的**最少**资料 ID，必须在该案例的 `catalogue` 里，至少一个。判「证据不足」时，列出你据以判断"资料不够"的那几份。

## 6. 标注纪律

1. **先核对摘要，再标注**：标注以摘要为准。摘要与原页有出入的，先改摘要，再标注。
2. **标注期间不运行任何评测**，也不查看任何策略或模型对这些案例的输出。
3. **留出集也正常标注**：标注时不需要知道哪些是留出案例。`splits.json` 只在评测时使用。
4. **拿不准的案例**：先按规则给出标签，在 `reason` 末尾注明"（存疑）"，标完后统一复查一遍。
5. **标完后不再改动标签**，除非发现与规则不符；改动时要在提交信息里说明原因。
