# 候选案例集：DFO Homebush The Big Shopping Week（2026-11-26）

本目录是**已标注并冻结**的候选数据（标签见 `labels_todo.json`），用于把案例从 3 个扩充到 23 个，并留出一部分作为独立测试集。`bf26.py eval --data` 可以读取本目录，用法见下文第 4 步。

## 内容

| 文件 | 说明 |
| --- | --- |
| `sources.json` | 12 份资料，均于 2026-11-26（悉尼当地）检查。格式沿用 `real_cases_2026_11_26/sources.json`。 |
| `cases.json` | 20 个候选案例（NC01–NC20），核对日均为 2026-11-26。每题的资料目录有 2–3 份。 |
| `labels_todo.json` | 人工标签表。20 个案例已于 2026-11-26 按 `LABELING.md` 标注完毕并冻结：11 个适用、5 个证据不足、4 个不适用。 |
| `LABELING.md` | 标注规则（草稿）。标注人定稿后才开始标注。 |
| `splits.json` | 开发集与留出集的划分，共 15 个开发案例、5 个留出案例。 |
| `SHA256SUMS` | `sources.json`、`cases.json`、`splits.json`、`labels_todo.json` 的校验和。标签冻结后才加入标签表。 |

## 资料来源与可信度

全部资料由商场 DFO Homebush 发布，包括：
- 活动页
- 活动传单
- 9 份单品牌优惠页
- 2 份商场门店页

摘要是经网页抓取工具整理后，再改写成的中文，**不是逐字摘录**，所以没有填 `quote` 字段。冻结前请逐条对照原页核实。传单的通用条款对所有品牌都适用，摘要只保留了与判定相关的部分。

**人工核实（2026-11-26 晚，标注人）**：27 段摘要逐条对照原页核对，25 段一致，2 段有出入，已按标注人在浏览器中看到的原页修改：

- **N01 活动页列表**：原页列表里有 Adairs「Black Friday Event」全店 30% off（11 月 25 日至 12 月 2 日）和 Oroton，没有 Rag & Bone「全店 25% off」。原摘要漏了前两项，又多列了后一项。
- **N11 Chatime 门店页**：原页当前展示的是 Peach Mango Summer 新品介绍，没有 $6 芒果红茶优惠。

这两处出入的来源：Claude 的网页抓取工具在当天下午和晚上两次读取这两页，返回的都是另一个版本——N01 含 Rag & Bone 25% 而不含 Adairs，N11 含 $6 芒果红茶。抓取工具从澳洲以外访问，返回的又是经模型整理的内容，很可能读到了缓存的旧版本。两次 Wayback 存档双方都无法打开，没能用存档来裁定。摘要以标注人在悉尼用浏览器直接看到的原页为准。

已知缺口：
- Rag & Bone「全店 25% off」：单独优惠页在检查当天无法打开，当晚由标注人再次确认仍打不开，也无法存档到 Wayback Machine。标注人看到的活动页列表里也没有这一项（见上文）。因此，在核实后的资料中，这条优惠没有任何出处。
- Nike Factory Store 和 Lindt 的商场门店页无法打开。
- 品牌官方今年的活动条款和门店目录没有找到可靠的一手来源，因此这批案例里没有「品牌活动条款」「品牌门店目录」两类资料。资料类型比首批 3 个案例单一。

**开发集结果意外暴露（2026-11-26）**：合并 PR #6 时，`tests/test_candidates.py` 里的一个旧测试因标签已填好而失败，失败信息打印出了 A、B 两组在开发集 15 题上的判定结果。这件事发生在标签冻结之后；5 道留出题的策略结果没有出现。因此保留现有划分不变。今后的报告把这 15 题的结果写作**开发集调试结果**，不作为泛化表现。该测试已改为在标签清空的临时副本上运行，失败时也不再打印评测表。

另需区分两类 C 组结果：`results/c_arm/cassette.jsonl` 是 BF26 首批 3 个案例的真实模型录制，回放 15/15 一致；本目录候选案例的 C 组真实录制尚未进行，要等判定器、查询策略和运行配置固定之后再录。

## 下一步（按顺序）

1. **立即存档原页**：优惠页通常在档期结束（约 11 月 30 日至 12 月 6 日）后下架。建议用 Wayback Machine 的 Save Page Now 逐个保存 `sources.json` 里的 URL，或者自己保存 PDF 和截图，再把存档地址补进对应资料。
2. **核实摘要**：对照原页逐条核对日期、折扣数值和限定条件。有出入时，以原页为准修改摘要，并重新生成 `SHA256SUMS`。
3. **人工标注**：先把 `LABELING.md` 里的待定项逐一选定，再在 `labels_todo.json` 填写标签（适用、不适用、证据不足）、理由和支持证据 ID。标注前不要查看任何策略或模型对这些案例的输出。
4. **评测**：`bf26.py` 已支持读取本目录。「商场门店页」只用来确认门店身份，不当作优惠依据。现有判定器是按首批 3 个案例的表述写的，预计在多数新案例上会判错，这是正常的。开发集用来改进判定器；留出集只在最后评测一次，不能据此调整规则。

   ```bash
   # 开发集（默认）；输出到 results/candidates_2026_11_26/dev/
   python3 bf26.py eval --data data/candidates_2026_11_26 --labels labels_todo.json
   # 留出集：必须显式指定，只在判定器定稿后运行一次
   python3 bf26.py eval --data data/candidates_2026_11_26 --labels labels_todo.json --split heldout
   # 单题轨迹
   python3 bf26.py check NC13 --data data/candidates_2026_11_26
   ```

   未标注的案例在报告中显示「未标注」，不计入正确题数。**标注完成前请不要运行评测或查看输出**，以免影响标注。

## 划分规则

`case_id` 的 SHA-256 值除以 3 余 0 的案例归入留出集。这条规则在标注和评测之前就已固定，由生成脚本写入 `splits.json`。如需调整比例，必须在标注之前改。
